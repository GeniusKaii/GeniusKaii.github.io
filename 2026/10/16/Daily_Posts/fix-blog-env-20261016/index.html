    又修了一次博客的本地环境

    2026-10-16 · Kaii 谈软件 · AIGC

    想在自己的终端里直接敲一句 hexo d -g 就把文章推上去，结果发现这台机器上的构建环境早就烂了：依赖目录不在版本库里、代理指向一个没起来的端口、运行时和 git 又各有一堆版本。

    顺便记一笔，免得下次再从头摸一遍。

    三个坑

    1. 代理：环境变量里配好了本地代理端口，但代理内核根本没起，于是包管理器上来就是 ECONNREFUSED。索性关掉代理走直连，包仓库反而通；github 的 HTTPS 超时、SSH 却是通的。
    2. 运行时：机器上同时躺着一旧一新两个大版本，hexo 4 这种老东西只认老的那个。
    3. git：某个版本的 git 在递归拉子模块时会直接报错，把 github: 形式的依赖装挂。

    现在怎么发

    依赖目录要是没了，就补一句（记得别带着那个死代理跑）：

    顺手把 hexo-cli 装到了全局，以后在任意目录都能直接 hexo。

    一个容易忽略的坑

    hexo deploy 是强推，而且只推构建产物这一份。也就是说：只存在于发布仓库、不在源码目录里的文件，会在某次发布时被悄悄抹掉——比如放在站点根目录做验证用的那个 txt。

    结论：凡是想要长期留在站点根目录的东西，都放回源码目录，让每次构建自己带上。

    碎碎念

    博客这东西，放着不管它自己也会烂：依赖会过期、环境会漂、连代理端口都会换。好在修一次能管很久——毕竟比起写文章，修环境的时间总是显得更值（更废）一点。
